# 无身份标签候选：通过的范围与失败的范围

## 结论

本轮在独立候选核心中删除了预设的活动 / 固定身份、trace 解码，以及
几何、出生、锁定、消行、路径和生命周期执行器。统一像素概率规则加
通用历史，在两条小型因果历史中替代了人工身份解释；完整游戏泛化
失败。上一版 373 条概率的推理模型继续作为有效基线，不将这个候选
作为纯净 BPC 游戏，也不据此声称已经获得自主认知结构。

基线提交：`c2f2d3d79a13726ff2f74fb4b28ca8d529beef46`。
外部世界仍使用之前同一份简化俄罗斯方块物理规则；规则写在
`environment.h`，只被游戏和审计器使用，核心 `model.h` 不引用它。

## 为什么不能直接清掉历史

从真实初始游戏 seed 96 出发，实际执行两条手写操作带：

| 历史 | 操作带前段 | 后段 |
| --- | --- | --- |
| A | `0000400` | `222222222222222222` |
| B | `0040000` | `222222222222222222` |

操作编号沿用外部环境接口：0 左、1 右、2 下、3 旋转、4 快速下落；核心
只收到编号，不使用这些名称。两次初始形状恰好都是方形。A 先把左方形
固定，再把右方形移到底部但不固定；B 的先后相反。然后都执行 200 次
编号 0。A 被相邻方形阻挡，B 被边界阻挡，因此每次画面都相同且不变。
下一次编号 1：A 可以移动，B 被阻挡。真实下一帧相差 4 位。

这里没有手工拼训练棋盘：所有中间画面均由实际执行产生。初始种子
选择属于外部反例测试，不给模型形状、身份或正确类别标签。

反例不只针对三帧：阻挡操作可重复任意次，因此任何固定长度的画面 /
操作窗口都可能相同。它证明必须保留某种历史信息；不证明必须保留
人工活动 / 固定类别。

## 新核心实际做了什么

每个物理位置、每个匿名端口使用同一条历史规律：

\[
M^{(a)}_{t+1}[i]=M^{(a)}_t[i]\oplus X_t[i]\oplus X_{t+1}[i].
\]

其他端口的记忆保持不变。五个操作端口和一个外部输入端口完全对称，
没有一个端口被指定为出生、锁定或身份更新。记忆不被解码成角色。
预测时记忆由模型自己的预测更新，训练时由真实下一帧更新。

一个扁平概率场统计真实下一位：

\[
P(X_{t+1}[i]=1\mid \text{物理支持},a)=\frac{n_1+1}{n+2}.
\]

同一规则作用于全部 300 位，包括外部显示。物理支持依次为共享的
半径 0、带地址的半径 0 / 1 / 2。遇到实际像素残差时，可打开整个物理
介质的条件支持；已有支持随后记录每次匹配的真实观测。所有支持都
在同一个表中，未设置功能分场。缺支持时回退到较小支持；无证据或
概率相等时保持当前位。没有评分、候选排序、规划器或神经网络。

整场景支持只是条件缓存，不是学习出的转移程序。固定窗口、支持
层次、概率阈值、回退法、XOR 历史规律和有限哈希表仍是设计假设；
这些事实必须保留在纯净性判断中。XOR 也不是完整历史的无损编码。

## 小型因果实验：成功，但不是完整游戏

两个版本都只用上述两条实际历史、各重复 100 次训练。训练等待 6 次
无效移动，冻结验证等待 200 次。只统计完整画面正确。

| 候选 | 冻结末步探测 | 两段各 226 步的完整自滚动 |
| --- | ---: | ---: |
| 原始三帧，无记忆 | 1 / 2 | 1 / 2 条完整历史 |
| 原始三帧，通用端口记忆 | 2 / 2 | 2 / 2 条完整历史，452 / 452 步 |

有记忆版本交换两条历史的记忆，末步变为 0 / 2；清空记忆为 1 / 2；
下一操作地址错位为 1 / 2。场的全部字节哈希在验证前后相同。

在加入整介质支持前，半径 2 的版本两条历史都在快速下落处失败：
落点附近的局部支持看不到远处来源。该失败保留在
`evidence/local_only_pair.txt`，可用 `GLOBAL_SUPPORT=0` 重现。
加全局支持解决这两条已训练历史，不构成跨形状泛化证据。

## 完整游戏：明确失败

先保留原始 17 条操作带的失败，再发现其缺少匿名端口 2；补入六条
手写操作带后，两个版本均重新冷启动训练同一份真实游戏流：
20,000 个方块，seed 55901，100,121 次操作，再加入上述 6,400 次因果
历史操作。五个端口的实际普通游戏暴露为
20,030 / 18,323 / 14,573 / 27,963 / 19,232，全部得到覆盖。
没有程序生成的教学棋盘，没有按棋盘选择动作的策略或目标评分。

训练结果：无记忆场 3,202,867 条，有记忆场 8,191,860 条。每个版本都
是一个独立概率场，两种场不会组合参与预测。整个缓存增长很多，但
没有获得上一版的可复用传播能力。

冻结测试用原八条种子流和新索引 24–27，每流 1,000 回合，最长 120
步，五种操作均参与。首错后停止统计该候选的预测前缀，但继续执行
真实世界，确保两个候选之后收到相同的回合流。两者实际世界均执行
468,734 步；表中前缀数包含每回合的首个错误，不是全部世界步数。

| 模型 | 正确预测前缀步 / 实际检查步 | 完整无错回合 |
| --- | ---: | ---: |
| 无记忆候选 | 16,157 / 28,157 | 0 / 12,000 |
| 通用记忆候选 | 15,616 / 27,616 | 0 / 12,000 |
| 上一版，新索引 24–27 | 155,895 / 155,895 | 4,000 / 4,000 |

上一版原八流的 312,839 步已在上一轮通过；本轮重新运行新增四流，
其步数与候选审计器执行的真实游戏逐流相同。

另用 23 条操作带进行五条新的冻结自滚动游戏流，种子
20261030–20261034，每条 10,000 个方块。出错后仍继续预测，只有真实
新回合初始画面与新的外部预览输入；不替换真实棋盘。

| 候选 | 完整画面正确步 | 含错误的游戏回合 |
| --- | ---: | ---: |
| 无记忆 | 21,821 / 250,434 | 2,940 / 2,940 |
| 通用记忆 | 16,450 / 250,434 | 2,940 / 2,940 |

这五条流使用新的 23 条操作带，不能与上一轮 17 条带的 244,017 步
直接当作相同数据比较。

额外的真实画面逐步回填诊断，仅用于检查一步条件概率，不属于自
滚动：有记忆版本 7,328 / 155,895 完整画面正确。背景位占多数的位
准确率不能代替完整游戏通过；即使供给真实历史，这个缓存也未形成
有效的可组合规则。

## 因果控制与工程核验

完整有记忆场的 100 回合前缀控制：正常 131 / 231，下一操作地址
错位 0 / 100，清除记忆 1 / 101，空场 1 / 101；全部正常回合也失败。
该完整场对两条末步探测为 2 / 2，清除或交换记忆均为 0 / 2。
控制只证明输入参与了小型结果，不把它升级为完整游戏成功。

严格 C11、O2、O3 编译均通过。O2 / O3 在完整 20,000 方块训练后生成
逐字节相同的有记忆场，SHA-256 为
`a229ffbbee35315bcc5585b60d20bba7be87ad6f6f42bca8e9ff783f60cc2755`。
两条因果历史、100 回合新流前缀、1,000 方块新流自滚动的 O2 / O3 /
UBSan 结果一致，UBSan 标准错误为空。各冻结验证均检查概率场全部
内存字节的哈希；没有验证期学习。

外部物理环境负责生成初始画面、终止后开始新回合和随机新预览，
预览输入沿用上一轮接口。这个外部输入协议也不是“完全由模型自发
建立接口”的证明。

## 本轮能支持的判断

可以用任务无关的物理历史替代预设身份，至少在这两条真实执行的
因果历史中成立。不能把“删除标签”与“删除信息”混为一谈，也不能把
“已记住场景”当作“学出可组合的游戏传播”。本轮没有闭合纯净 BPC
完整游戏。下一项尚待解决的核心问题是：仅凭真实残差，如何形成可
复用的传播支持，而不是依赖角色执行器或整场景缓存。
