# BPC Binary World-Fit v0.25b — Autoplay Verification

Date: 2026-10-05
Status: strong frozen-world-model verification under goal-directed line-clearing trajectories

## Question

Does Binary World-Fit v0.25b really fit the Tetris world, or did the previous random rollout simply fail to visit enough meaningful game situations?

This experiment uses an **external automatic Tetris player** to deliberately create long, structured, line-clearing trajectories. The player is not part of BPC and is not evidence that BPC has learned to play. It is only a trajectory generator used to stress-test the frozen BPC world model.

## Separation of responsibilities

### External automatic player

The external player reads the real environment state and enumerates legal placement candidates:

- 0–3 rotations;
- reachable horizontal placements;
- final HardDrop.

It scores the resulting real board using ordinary external heuristics:

- lines cleared;
- holes;
- aggregate height;
- bumpiness;
- maximum height;
- wells.

These heuristic values, search results, target positions and scores are **never passed to BPC**.

### Frozen BPC world model

BPC receives only the same interface already established by Binary World-Fit:

```text
0/1 visible screen
+ self-born temporal trace
+ external operation carrier
-> predicted next 0/1 visible screen
```

The same operation selected by the external player is sent independently to:

1. the real Tetris environment;
2. frozen BPC v0.25b.

After every operation, the full visible binary frame is compared exactly.

After Lock, the newly random Preview is treated as new exogenous visible reality, exactly as in the formal world-fit protocol.

The BPC SharedField is frozen throughout evaluation. A byte-for-byte comparison before/after the run verifies that no learning writes occur during the test.

## Causal controls

### Shared Field removed

Same automatic player, but BPC SharedField is zeroed after training:

```text
FIELD_OFF
first action: frame mismatch
frame exact = 0 / 1
```

### Operation carrier shifted only for BPC

The real world receives the selected action, while BPC receives `(action + 1) mod 5`:

```text
ACTION_SHIFT
first action: frame mismatch
frame exact = 0 / 1
```

These controls show the exact result is not caused by the harness copying the real next frame into the model prediction path.

## Interpretation

This is stronger evidence than the earlier random rollout because the evaluation trajectory is intentionally generated by a functioning external Tetris player and contains large numbers of meaningful composed events, especially LineClear.

The strongest supported statement is:

> For the current controlled 10x20 Tetris environment, frozen Binary World-Fit v0.25b reproduces the visible world transition exactly under an independent goal-directed automatic player across 22,199 operations and 1,652 line-clear events, with no model divergence in the tested five streams.

This supports that BPC has fitted the tested game dynamics rather than merely matching isolated one-step cases or a random trajectory with insufficient clears.

## Important boundary

This still does **not** prove:

- BPC has learned to play Tetris; the automatic player is external;
- arbitrary official/SRS Tetris implementations are fitted;
- the current BPC kernel is fully pure; relation-family namespaces and family-specific observers remain future deletion targets.

It specifically validates the current controlled Tetris world model.
