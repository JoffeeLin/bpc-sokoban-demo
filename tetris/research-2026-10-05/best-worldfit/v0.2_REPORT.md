## Deleted scaffold

v0.1 still retained the v1.7 learned three-bit `QGate` that decided when Spawn was allowed after a lock/clear process.

That gate received three process-level booleans and learned a quiescence condition. Although learned rather than Tetris-named, it was still a dedicated scheduling function.

v0.2 deletes:

- `QGate` state;
- `train_qgate()`;
- `qgp()`;
- `active_present` / `row_pending` scheduling logic.

## New execution rule

After the external one-step Down consequence, downstream relations are simply allowed to participate on every microstep:

```text
Spawn relation
+ LineClear closure relation
-> update current state
-> repeat
-> stop only at fixed point
```

There is no explicit `Lock -> Clear -> Spawn` schedule and no learned gate deciding which downstream family may run first.

The implementation intentionally evaluates Spawn before the clear relation in each microstep, then repeats. Thus correctness cannot be attributed to reproducing the reference engine's procedural order.

## Interpretation

This deletion supports a stronger statement than v0.1:

```text
world functions do not need a separate learned process scheduler
```

The same already-learned downstream relations can remain active and repeatedly rewrite the visible state until the field reaches a fixed point.

This is closer to the desired BPC mechanism:

```text
function birth
-> function reuse
-> multiple functions coexist
-> repeated coupling / re-entry
-> stable higher-order consequence
```

rather than:

```text
researcher defines execution order
-> scheduler decides which function runs next
```

## Next purity target

The largest remaining duplicated mechanism in this fully-observable baseline is the separate execution vocabulary for Move / Rotate / Spawn and the row-carrier detector. The next safe deletion should reuse later v3.x evidence to move these toward one generic relation-propagation equation, while keeping the v2.1 fully-observable rotation world and the complete regression suite frozen.
