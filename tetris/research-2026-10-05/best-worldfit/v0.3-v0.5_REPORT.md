# BPC Best World-Fit v0.3–v0.5 — 删除 LineClear 行选择与执行顺序

Date: 2026-10-05
Status: v0.3 partial positive / v0.4 negative / v0.5 promoted current baseline

## Baseline

Starting point is Best World-Fit v0.2:

- fully observable `Visible Active + Visible World + Visible Preview + Action -> next visible state`;
- no independent learned LineClear propagation table: row relocation reuses learned one-step Down;
- no QGate / explicit Lock->Clear->Spawn scheduling gate;
- downstream learned effects repeatedly relax to a fixed point.

Formal v0.2 regression: 8 seeds, 40,000/40,000 one-step states and 312,839/312,839 rollout ticks exact.

## v0.3 — remove `detectrow()` / top-1 row selection

Old code selected the strongest full-row carrier, applied one clear, then searched again.

v0.3 instead snapshots all row carriers and lets every mature carrier participate. Each carrier still reuses the same learned Down function for relocation. No max/top-1 winner is chosen.

Normal top-to-bottom carrier application retained full capability:

- 1/2/3/4 row stress: 10,000/10,000 exact;
- 8-seed one-step regression: 40,000/40,000 exact;
- 8-seed rollout: 312,839/312,839 exact.

However reversing only the carrier execution order produced:

- 1 row: 2,500/2,500;
- 2 rows: 0/2,500;
- 3 rows: 0/2,500;
- 4 rows: 0/2,500.

Therefore top-1 row selection is unnecessary, but v0.3 still hides a causal ordering scaffold in sequential carrier execution.

## v0.4 — naive simultaneous hole translation: negative

Attempted to remove row order by making all full-row hole carriers shift upward together every microstep while content filled holes through learned Down.

Result:

- 1 row: 2,500/2,500;
- 2/3/4 rows: 0/2,500 each.

Failure mechanism: adjacent hole carriers pass through/drag each other, repeatedly vacating information instead of representing multiple independent missing-information instances.

This rejects the naive rule `all holes translate upward unconditionally`.

## v0.5 — synchronous local exclusion carriers

v0.5 keeps all row carriers simultaneous but gives them only a local exclusion interaction:

- a hole is a local empty-information carrier;
- it may exchange with the immediately-above row only when that source row is not itself another hole;
- non-adjacent holes may propagate in parallel;
- adjacent holes cannot pass through each other;
- visible content transfer still uses the same learned one-step Down function;
- there is no winning row and no ascending/descending clear schedule;
- there is no separate LineClear propagation parameter table.

The mechanism is therefore:

```text
full-row residual/carrier birth
-> multiple simultaneous hole carriers
-> local carrier exclusion/interference
-> learned Down reuse for visible content
-> synchronous repetition to fixed point
```

## Scientific interpretation

The experiment separates three claims:

1. A top-1 row selector is not required.
2. Simply removing the selector is not enough if program order still resolves interacting carriers.
3. Multiple deletion events can instead exist as local carrier instances whose interactions are handled synchronously, while the already-born Down function supplies the actual relocation.

This is closer to the BPC target:

```text
function birth
-> function reuse
-> multiple function/carry instances coexist
-> local interference/coupling
-> higher-order fixed-point consequence
```

rather than a Tetris-specific sequence of `find row -> clear row -> find next row`.

## Remaining purity frontier

v0.5 is not final Pure BPC. Important remaining scaffolds include:

1. `rowc()` still explicitly groups ten horizontal cells into a row carrier;
2. Move / visible Rotation / Spawn still have distinct learned/execution structures;
3. Active / World / Preview are still externally identifiable visible information channels;
4. external Action is still a dedicated input channel;
5. local address geometry is supplied;
6. carrier exclusion is currently an explicit generic local rule rather than itself learned from residual dynamics.

The next highest-value game-fitting experiment is to remove the explicit row grouping by replacing `rowc()` with a generic boundary-to-boundary closure wave / local address-carry process, while retaining the v0.5 full regression suite.
